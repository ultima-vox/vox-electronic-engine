# VOX FX — Arena session handoff and integration policy

This file is an **origin marker** for FX Arena sessions. A new Arena session must branch from the **current** `next/fx-development` after this document and `.github/workflows/fx-arena-handoff.yml` were added. Existing Arena branches that lack this history are intentionally excluded from automatic PR discovery.

## Branch roles

- `next/fx-development`: durable FX integration branch; never assign concurrent Arena sessions to write directly to it.
- `arena/*`: one Arena session per branch, with independent commits and its own lifecycle.
- `next/standalone-suite`: cross-product integration after FX review, not an Arena workspace.
- `main`: protected release baseline; no direct Arena merges.

## Automatic handoff

A push to an Arena branch **created from this marker-bearing integration history** runs `fx-arena-handoff.yml`. The workflow:
1. Verifies that the branch and its merge base with `next/fx-development` both contain this marker.
2. Compares against `next/fx-development` and skips branches with no new commits.
3. Reuses any existing open PR for the source branch or creates one **Draft PR targeting `next/fx-development`**.
4. Never auto-merges, rebases, force-pushes, cherry-picks, or changes Arena code.

Creating a PR with `GITHUB_TOKEN` requires repository Actions permissions to allow creating pull requests; a permissions failure is visible in that workflow's logs. GitHub may not trigger new `pull_request` workflows for PRs generated by `GITHUB_TOKEN`; do not mistake an absent CI run for PASS.

## Review and qualification

The TL reviews the exact diff, scope, API/state and DSP realtime safety, content fidelity, test evidence and conflicting Arena work. Accept changes selectively with ordinary PR merge or deliberate cherry-pick. **No automatic approval or merge.**

Heavy Windows `build` and `suite` jobs are skipped for FX Arena Draft PRs targeting `next/fx-development`; all other product PRs retain their normal rules. To **explicitly opt into** an exact-head FX Windows suite while Draft, add `[RUN_FX_SUITE]` to the PR body in a new edit; adding the token must be a transition from absent to present. Remove it before another opt-in. The legacy targeted `[RUN_FX_PROCESSOR]` path is limited to #156. Owner/CI authorization and runner budget still apply.

No Linux/Windows unit result by itself proves Cubase/REAPER hosting, listening approval, installed artifacts, licensing, or release readiness. FX-T18 and other FX release gates remain open until separately verified.

## New Arena handoff

Use `next/fx-development` as the source branch. Arena creates a new `arena/*` branch and pushes changes; the PR is generated when a pushed branch contains genuine commits beyond the shared base. After the TL accepts a checkpoint into the integration branch, new Arena sessions start from its new HEAD. Do **not** force-sync active Arena branches.

If a session started before this workflow/marker was installed, either finish it and submit a manually reviewed PR, or start a new Arena from the current integration HEAD. Never graft old work blindly onto the new branch.

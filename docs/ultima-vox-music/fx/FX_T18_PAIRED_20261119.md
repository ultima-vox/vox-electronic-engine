## Overrun interpretation

- The historical 96 kHz/64/4 result was ~704 µs thread CPU against 666.67 µs; it was not just lost scheduling time. The earlier exact miss did not repeat in these baseline A/B runs. A separate CPU deadline failure **did** reproduce: baseline B, no Pattern, 96 kHz/128/8, 4 callbacks over 1333.33 µs, max wall 1490.37 µs / CPU 1492.18 µs. This establishes real callback work pressure, not the precise call site or cause of the old outlier.
- For the historical 96 kHz/64/4 no-Pattern case, baseline median wall 222.15 / 254.78 µs; current 146.20 / 151.19 µs. With Pattern the same case moved from 231.58 / 228.77 to 159.31 / 160.82 µs. These paired medians show increased headroom; individual maxima vary. In the new code the granular branch no longer performs unused procedural-noise filtering or per-sample pitch math. It still advances its RNG once per layer sample and evaluates pitch at grain admission. Ring indexing drops integer divide/modulo from the per-grain hot path. Program curves are evaluated once per voice sample, neutral filter/pitch multipliers skip exponentiation. Pool capacities, filter cadence, window and interpolation stay unchanged.
- With an intentional same-core competitor, the worst wall callback was 13,402.43 µs but consumed 1355.31 µs CPU. All 267 deadline overruns in this run were **wall-only**, consistent with loss of scheduling time under CPU contention; no such run can establish drop-out-free operation.

## Reproduce

Build each exact source with [the pinned Linux native harness](evidence/run-linux-native-fx.sh) in separate output dirs. On this two-CPU VM, use `ulimit -s 1024` and `VOX_FX_TIMING_THREAD_CPU=1 taskset -c 0 <out>/FxRuntimeStressTests`; run baseline A, current A, current B, baseline B in that order without concurrent build work. Use `VOX_FX_STRESS_AUTHORED=1` and `VOX_FX_STRESS_TYPICAL=1` for the separate profiles. For the deliberate contentious diagnostic only, run `taskset -c 0 yes >/dev/null` alongside authored and stop it when the run ends. Aggregate `misses wall/CPU/wall-only` separately; assess deadlines against each row, not an aggregate mean.

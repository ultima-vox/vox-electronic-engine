# Per-layer Glitch slices — development checkpoint

**Draft / HOLD / NO MERGE.** Implementation `9eaebf68aee23f5bfe11a75f65ffeeffa9302a09`, based on the [TL-reviewed clock and tail checkpoint](HOST_CLOCK_AND_TAIL_20261119.md). This advances source authoring and adds regression coverage, not release acceptance.

## What changed

- Select a **Glitch** layer in **Source / Key** to set the grid (**1/8, 1/16, 1/32**), read mode (**alternating forward 1×/2×, forward, reverse**) and four repeating slice gates. **Reset slices** restores the exact legacy settings. These are per-layer structural edits for **new events**, not host parameters or Trigger Pattern steps. Generate and Mutate preserve them; the 19 host IDs are unchanged.
- Playback still uses the layer's own first 256 synthesized samples. The clock advances at current tempo from the layer's event onset; it does not align to host PPQ, maintain a fixed capture time in milliseconds across sample rates, or record an external input. Nondefault settings mute the capture lead-in, fade in the first enabled playback, and mute the source on rests even with negative Character. Filters and shared FX can still ring through rests. The full default combination retains the historic lead-in and negative-Character bleed, so Reset can sound different from an edited mask.
- With a native peer, opening Source puts focus on the layer selector; the controls have a local tab order and accessible titles; Escape or Close dismisses the panel and returns focus to the opener if it is still available. The regression runs offscreen and does **not** establish host key delivery, platform focus restoration, screen-reader output, or DPI readability.
- FPRG v8 appends four packed words after the v7 grain block. Untouched Glitch settings retain v6/v7 writes; v1–7 read with the legacy defaults. Invalid grid, read mode, reserved bits, truncation and a redundant default-only extension are rejected. An older reader will reject a v8 Program rather than silently flatten the new settings. [TL reviewed the schema and integrated this checkpoint for development only](https://github.com/ultima-vox/vox-electronic-engine/pull/156#issuecomment-7034953740). See the [1.0 user compatibility note](USER_NOTES_1_0.md). Save commit/overwrite policy, `.voxfx` update handling, and offered drag ownership were not changed.

## Как читать матрицу

- `actual_source_path` — пути в репозитории **на `source_sha`**, не обязательно в текущем checkout. Для открытия: `https://github.com/ultima-vox/vox-electronic-engine/blob/<source_sha>/<path>`.
- `workspace` / `panel` — **цель** компоновки. `attachment_or_current_ui` / `notes` — текущее статическое свидетельство, где это существенно. `partial` — только неполное покрытие целевого UI, а не отсутствие DSP. `gap` — требуется отдельный проверяемый endpoint/компонент; пустой `parameterID_or_controller_method` не является идентификатором. `owner` указывает роль для проверки, не назначение агента.
- `kind=host-param` — строка на уникальный параметр, не на каждый его виджет. `default` сохраняет plain-значение из манифеста (включая его float-печать). Для структуры `contextual` означает значение из действительного объекта/кита, а не 50% или reset к нулю. `gesture`, `reset`, `undo` описывают контракт переноса; они не заявляют, что новый жест уже работает.
- Структурные строки покрывают семейства контролов и сценарии ТЗ, не количество будущих экземпляров на экране. До интеграции требуется проверить каждый видимый интерактивный контрол на конечном SHA. `test_case` ссылается на **предлагаемые** проверки из [сверки](DS00_RECONCILIATION.md#проверки-для-будущей-интеграции); это не выполненные тесты.
- Drums host и поля структуры сверены с [аудитом #158](https://github.com/ultima-vox/vox-electronic-engine/blob/065d2be5627be6bac10098b2dbedf6fe65944807/docs/ui/ds-00/UI_BINDING_MATRIX.csv) и тем же живым SHA Drums. Для FX старый аудит является историей; строки проверены по свежему коду. Манифесты `parameters.csv` и runtime-привязки владеют значениями — копия в матрице не заменяет их.

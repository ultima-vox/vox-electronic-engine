# Vox Trance Engine — production-проект, предложение v0.1

Дата: 25.10.2026.
Базовый main при подготовке: b076a53d8900b53433e8aa4fdb1027c8f2bed135.
Статус: проектное предложение для обсуждения, не утверждённая замена master spec.
Документ описывает целевое поведение; перечисленные функции не объявляются реализованными.

## 1. Зафиксированные требования владельца

- Windows 10–11 x64; VST3 x64.
- Cubase 12–15; актуальная стабильная ветка REAPER x64. Точные сборки включаются в release manifest.
- Один VST rack.
- Bass, Lead, Keys, FX; добавить Drums как полноценный модуль того же rack.
- Генерация тембров и MIDI-паттернов; отдельные пресеты инструментов.
- Перенос MIDI на дорожку DAW.
- Генерация полностью локальная, без нейросетей и сетевых сервисов.
- Keys: синтезаторные клавиши, plucks, bells, pads, piano/electric piano.
- Первый стиль разрешено выбрать проектировщику.
- Цель — production-релиз, не MVP/POC.
- Сообщённые дефекты: генерация не работает; бас воспринимается как непрерывный «пиип».
- Предложение владельца: сначала пустой rack, затем инструменты по одному.
- Предлагаемое новое продуктовое имя: Vox Trance Engine.
- Последующее предложение владельца: разделять racks, в том числе по подстилям, для модульного распространения/монетизации. Что именно означает отдельный rack — пакет внутри общего host или отдельный VST3 — ещё не уточнено.

## 2. Инженерное решение и границы

Выбран первый стилевой пакет: Full-on Psytrance. Это проектный выбор, а не утверждение, что он уже реализован.
Рабочая стартовая сцена: 145 BPM, 4/4; темп не зафиксирован в движке и синхронизируется с хостом.

Пустой rack допустим как внутренний этап разработки и проверки жизненного цикла.
Он не является доказательством качества инструмента или первым музыкальным результатом.
Первый слышимый интегрированный результат: rack + один законченный Bass + генерация Sound/Pattern + MIDI export + восстановление проекта.
После его проверки добавляются инструменты последовательно.

Целевая линейка содержит все пять семейств и один законченный стартовый стилевой набор.
После предложения о монетизации возможны самостоятельные production-пакеты, например Bass Full-on, затем Drums Full-on. Это не исключает остальные инструменты из общего проекта.
Объём первого продаваемого пакета и общий релизный комплект ещё не утверждены. Каждый выпущенный пакет проходит полный применимый production gate; слово «модуль» не оправдывает незавершённые функции.
Внутренние этапы разработки не подменяют качество production-релиза.
Goa, Dark Psy, Forest и другие стили добавляются отдельными профилями после первого пакета; кнопки для отсутствующих пакетов не показываются как работающие.

Drums в этом продукте уместен, но число типов ударных не определяет сложность.
Нужны kit state, назначения нот, одновременные голоса, choke groups, хвосты, уровни и согласованная генерация с Bass.
Drums — отдельный инструмент внутри rack, не отдельная универсальная DAW.

Переименование интерфейса не должно автоматически менять VST3 class/FUID, host parameter IDs, InstrumentId и SlotId.
Перенос или переименование GitHub-репозитория данным документом не предлагается.
Совместимость со старыми проектами до ответа владельца сохраняется как ограничение.

### Отличия от существующих issue #10/#11

- Продукт фокусируется на trance, первый законченный пакет — Full-on Psytrance.
- Drums предлагается включить в этот продукт; это меняет прежний запрет из product split.
- Keys становится обязательным инструментом.
- REAPER становится вторым целевым хостом.
- Нужны полифонические длинные фразы и независимая генерация звука.
- Новые требования требуют явного пересмотра соответствующих контрактов и миграций до изменения кода.
- Этот proposal не переписывает молча действующие master issues и не отменяет существующие проверки.

## 2A. Разделение rack, инструмента и коммерческого пакета

Это предложение, требующее уточнения значения слова «rack» у владельца.

| Сущность | Назначение | Пример |
| --- | --- | --- |
| Host / rack container | Общий VST3, slots, routing, state, UI shell | Vox Trance Engine |
| Instrument module | DSP и редактор семейства звуков | Bass, Drums, Lead, Keys, FX |
| Style/content pack | Профили генерации, presets, patterns, kits, scenes и необходимые ресурсы | Bass Full-on, Bass Goa, FX Dark Psy |
| Rack/Scene preset | Сохранённый набор выбранных инструментов с маршрутизацией | Full-on starter rack |

Подстиль обычно требует другого контента и правил генерации, а не копии host или DSP.
Если стиль действительно требует нового синтезатора, добавляется отдельный instrument module через тот же контракт.
Пользователь может смешивать пакеты: например Goa Lead + Dark Psy FX + Full-on Bass.

Предлагаемая упаковка:
- общий host поставляется вместе с приобретённым пакетом;
- отдельные instrument+style packs;
- style bundle для нескольких инструментов;
- полная коллекция как комплект пакетов.
Стоимость, конверсия и коммерческая эффективность не оцениваются без данных.
Один и тот же pack не требует отдельной копии processing/state/routing кода.

У каждого pack стабильные packId, версия, compatibility range, список instruments/content/resources и лицензия.
Наличие пакета и право использования — отдельные состояния.
Модуль не должен считаться повреждённым только потому, что конкретный style pack не установлен.
Загрузка preset не исполняет произвольный код из content pack.
Пакеты 1.0 могут быть только данными для встроенных instruments; внешние бинарные modules не нужны для монетизации.

Полностью offline runtime сохраняется:
- content ставится из локального установщика/архива;
- если лицензирование будет выбрано, возможен локально проверяемый подписанный license file;
- точная политика activation/device binding/transfer пока не выбрана;
- покупка, загрузка и выдача лицензии могут происходить вне DAW, без постоянного соединения плагина.

Политика открытия проектов при отсутствии ресурса или лицензии должна быть явно утверждена до реализации.
Нельзя молча подставлять иной инструмент, терять настройки или включать скрытый online check.
Предпочтительная продуктовая цель — не разрушать воспроизведение ранее сохранённых проектов; юридическая и лицензионная реализация ещё не определена.

Альтернатива: отдельные VST3-продукты Bass/Drums/etc из общего кода.
Она возможна, но увеличивает число plugin identities, install/test matrices и путей переноса проектов.
Разделение по каждому подстилю на отдельный VST3 не рекомендуется как исходная архитектура без конкретной причины.
Не делать выбор за владельца: общий VST3 + packs или отдельные VST3 SKU остаётся открытым решением.

## 3. Проверенные факты и неизвестное

В просмотренной реализации уже есть Rack, Router, providers, transport, presets/state, MIDI export и instrument-модули.
В Sequence.h одна нота на шаг; maxSteps = 64.
В InstrumentAbi.h VoxPatternV1 также имеет фиксированные 64 шага.
BassGenerator создаёт 16 шагов; просмотренный LeadGenerator — 16 или 32.
Это ограничения просмотренного кода, а не заключение о качестве его звучания.

Описание «пиип» не устанавливает причину.
До воспроизведения дефекта нельзя выбирать между неверным preset mapping, огибающими, MIDI NoteOff, маршрутизацией, регистрами и собственно DSP.

Зелёный CI не подтверждает звук, поведение DAW или субъективное качество пресетов.
Текущая UI-ветка/PR #43 должна быть сопоставлена с окончательно выбранным workflow до интеграции.

## 4. Rack и разделение ответственности

Сохранить существующую ёмкость до 16 слотов.
Пустой слот не создаёт инструментальные голоса и не расходует ресурсы активного синтезатора.
Несколько экземпляров одного инструмента разрешены.

Каждый слот хранит:
- стабильный SlotId и InstrumentId;
- Sound, Pattern, Generator profile и их версии;
- MIDI source: Host / Internal / Both;
- входной MIDI-канал или OFF, зоны клавиш/velocity, transpose;
- mute, solo, level, pan, audio destination;
- macros, modulation, insert effects;
- независимые sound lock и pattern lock;
- seed и настройки генератора.

Host / Internal / Both явно видны. Исторический AUTO при миграции сохраняет прежнюю семантику; он не должен незаметно включаться в новых сценах.
Проигрывание MIDI с дорожки после экспорта не должно дублироваться внутренним паттерном без выбранного Both.

Core отвечает за время, маршрутизацию, владение нотами, состояние, ресурсы и координацию.
Инструмент отвечает за DSP, доступные параметры, звуковые ограничения и музыкальные правила.
Стилевой пакет содержит профили, контент и правила инструментов, а не новый параллельный engine.

Внутренние модули статически поставляются с плагином.
Внешний DLL loader и размещение сторонних VST внутри rack в релиз 1.0 не входят.

## 5. Состав инструментов

| Инструмент | Целевой звук | Генерация |
| --- | --- | --- |
| Bass | Rolling, offbeat, sub, pluck, acid-like; phase/retrigger, amp/filter/pitch envelopes, saturation, glide | Паузы под kick, ритм, акценты, длины, регистр, вариации фразы |
| Lead | Mono/poly; saw/unison, wavetable/FM, pluck, acid-like | Мотив, повтор с развитием, ответ, arp, окончания |
| Keys | Poly; plucks, bells, pads, synth piano, electric piano | Аккорды, обращения, голосоведение, stabs и arp |
| FX | Risers, downlifters, impacts, sweeps, lasers, zaps, textures | Тип события, старт, длительность, target beat и развитие |
| Drums | Kit: kick, closed/open hats, clap/snare, percussion, дополнительные слои | Отдельные дорожки kit, groove, акценты, вариации и fills |

### Bass

- Насыщенный гармониками источник с подавлением aliasing в осцилляторах; не использовать необработанный saw как конечное production-решение.
- Отдельные amp и filter envelopes; управляемая короткая pitch envelope.
- Управление фазой/retrigger; mono/legato, glide, note length, drive и level.
- Oversampling там, где измерения нелинейного тракта показывают необходимость.
- Фабричный Init Psy Bass сразу звучит в подходящем регистре.
- Короткая нота, длинная нота и одинаковые ноты подряд проверяются раздельно.
- Generate Sound меняет допустимые параметры тембра, не MIDI-ноты.
- Паттерн rolling не обязан случайно менять высоту каждой ноты: основной тон и редкие вариации имеют отдельные правила.

### Keys и piano

Synth piano и electric piano означают синтезируемые тембры.
Реалистическая имитация акустического рояля не считается обещанной этим proposal.
Если владелец требует реалистическое акустическое piano, нужен отдельный выбор sample content/объёма поставки/лицензии.
Нейросеть для этого не требуется, но ресурсы и DSP-подход отличаются.

### Drums

- Внутри одного слота — kit и отдельные pad lanes.
- Событие включает pad/note identity; редактирование одного pad не меняет остальные.
- Closed/open hi-hat поддерживают явно заданную choke group.
- Kick и синтетическая percussion могут синтезироваться; hats/claps/snare используют подходящий синтез/встроенные one-shot ресурсы после выбора контента.
- Импорт пользовательских WAV one-shots: проверка формата, root/note assignment, trim, gain и сохранение ресурсов.
- Отсутствующий sample вызывает явную диагностику и сохраняет его identity; инструмент не подставляет другой звук.
- При Generate Scene groove kick доступен Bass как ограничение; это не автоматический mastering.
- Раздельные MIDI-дорожки pad и отдельные слоты Drums допускают смешивание в DAW без обязательного сложного multi-pad audio routing.
- Per-pad audio outputs не обещаны релизом 1.0; slot outputs обязательны.

## 6. Музыкальная модель

Новая модель Pattern должна поддерживать:
- абсолютный старт и длительность в музыкальных долях;
- несколько одновременных нот и перекрытия;
- velocity, probability, articulation, stable event identity;
- отдельные drum lanes;
- фразы 1, 2, 4, 8 и 16 тактов;
- отдельные musical automation lanes и внутреннюю sound modulation;
- редактируемое выделение и заблокированные события.

Step editor — представление этой модели, а не второй источник нот.
Piano roll, realtime scheduler и MIDI export работают с одним подготовленным event plan.

Изменение Sequence/Content API требует версии v2, явного адаптера v1 -> v2 и обновления ABI границы.
Старый 64-step payload не переинтерпретируется как новая структура.
Размеры, число событий и пределы модуляции ограничены и валидируются до публикации в audio thread.
Численные бюджеты утверждаются после baseline на целевом CPU, а не назначаются как якобы измеренные.

## 7. Генерация

Команды каждого инструмента:
- Generate Sound;
- Generate Pattern;
- Generate Both;
- Mutate Sound / Mutate Pattern;
- Mutate Selection для выбранных событий;
- Reset to Init;
- Undo / Redo.

Общий контекст: style, tempo, meter, root/scale, progression, phrase length/position, energy, density, complexity и seed.
Пользователь видит только настройки, имеющие смысл для выбранного инструмента.

Sound generation — алгоритм допустимых сочетаний параметров с зависимостями, а не независимый random каждого knob.
Pattern generation — музыкальная грамматика с повтором, развитием, паузами и окончаниями.
Для Keys используются chord voices и голосоведение; для FX — семантика событий, для Drums — kit lanes.

Sound seed и Pattern seed независимы, сохраняются с версиями генератора.
Одинаковый seed без версии алгоритма не является гарантией совместимости.
Сохранённый проект хранит полученный patch и ноты; загрузка проекта не запускает заново текущую версию генератора.

Генерация идёт вне audio thread.
Пользователь может прослушать кандидата, сравнить A/B и принять или отменить его.
При генерации во время playback новый Pattern вступает на согласованной границе, с безопасным завершением принадлежащих старому плану нот.
Кандидат не заменяет активный результат, если валидация не прошла.

Generate Scene связывает музыкальный контекст инструментов.
Он уважает раздельные sound/pattern locks и ручные правки.
Контекст Bass учитывает явную kick lane либо настраиваемую сетку kick, если Drums отсутствует.
Плагин не анализирует автоматически посторонний kick на другой дорожке без отдельного согласованного audio-input workflow.

## 8. Случайность и воспроизводимость

По умолчанию зафиксированный Pattern играет одинаково.
Для probability/evolving pattern предусмотрены явные режимы:
- Fixed phrase: материализованный вариант повторяется;
- Evolving: решения меняются по номеру цикла от project position и seed.

Определить устойчивый origin фразы в музыкальном времени и поведение при seek/loop.
Нельзя основывать музыкальный результат только на количестве вызовов processBlock или на времени системы.
Одинаковый участок должен воспроизводиться согласованно при старте с разных позиций, offline render и изменении block size в пределах выбранной политики.

Для evolving pattern команда Capture фиксирует конкретную длину и вариант.
Drag MIDI экспортирует зафиксированный вариант или явно выбранный диапазон; результат не генерируется случайно ещё раз при drag.

## 9. MIDI/WAV и выходы

- Drag MIDI и Save MIDI для выбранного слота.
- Scene MIDI: Standard MIDI File type 1 с отдельными треками слотов; для Drums — опция отдельных pad tracks.
- Импорт сохраняет длину фразы, ведущие/конечные паузы, длительности и velocity.
- Tempo metadata по умолчанию не перезаписывает темп проекта-приёмника.
- Notes only и Notes + supported controllers выбираются явно.
- Slide/pitch bend экспортируются с документированным диапазоном и необходимым reset.
- Channel-wide bend не используется как независимый glide каждой ноты аккорда.
- Внутренняя модуляция не объявляется эквивалентной MIDI CC.
- MIDI output для записи в DAW — отдельный тестируемый workflow.
- Drag WAV и Save WAV для зафиксированного звучания, особенно FX, с dry/wet и tail policy.
- WAV render идёт вне audio callback, с отменой и без изменения live state.

Audio outputs: Main stereo + опциональные stereo slot buses до 16.
Каждый слот по умолчанию идёт в Main; выбор отдельного выхода не дублирует его в Main.
Топология доступных host buses стабильна; активация дополнительных выходов тестируется в каждом DAW.
Per-slot inserts сохраняются со слотом. Общий limiter не маскирует перегрузку и не меняет звучание незаметно.

## 10. Presets, state и ресурсы

Типы: Sound, Pattern, Generator/Style, Kit, Effects и Scene.
Kit — Sound-подтип Drums со всеми pad assignments, ресурсами и настройками choke.
Sound load не заменяет Pattern; Pattern load не заменяет Sound.
Scene сохраняет сочетание инструментов, маршрутизацию, эффекты, результаты генерации и seeds.

Factory и User разделены.
У контента есть instrument/style/type/version и resource references.
Проект сохраняет фактические значения, а не только имя текущего factory preset.
Обновление factory pack не меняет уже сохранённый звук.
Для пользовательских samples нужны сбор ресурсов для переноса проекта и явные missing-resource diagnostics.

State load транзакционный: parse -> validate -> prepare -> commit.
Повреждённое состояние не уничтожает последний валидный runtime.
Unknown/incompatible payload сохраняется для восстановления.
Операции удаления user presets доступны с отменой/подтверждением по принятой UI-политике.

## 11. Интерфейс

Без отрисовки до явной команды владельца.

### Структура

- Header: Scene, Undo/Redo, A/B, host tempo, root/scale, MIDI source, Panic, meters.
- Rack слева: slot, instrument, channel, preset, mute/solo, activity, level и output.
- Workspace: Sound / Pattern / Modulation / Effects.
- Generator справа: style, role, подходящие параметры, Generate Sound/Pattern/Both, locks, варианты.
- Preset browser открывается отдельной панелью, с фильтрами Instrument/Style/Type.
- Нижняя клавиатура для synth slots; pad bank для Drums.
- Скрываемые вторичные панели; рабочие параметры и piano roll имеют приоритет над artwork.

Sound page зависит от инструмента:
- Bass: oscillator, amp/filter/pitch envelopes, filter/drive и macros;
- Lead/Keys: synthesis, voices, unison, envelopes;
- FX: event family, duration/target, modulation curves;
- Drums: pads, sample/synth controls и choke settings.

Pattern page:
- notes + velocity для synth;
- polyphonic piano roll для Keys;
- pad lanes для Drums;
- event timeline для FX;
- однозначное указание slot/instrument, которому принадлежит редактор.

Style влияет на Generate, а не неожиданно на уже звучащий patch.
Disabled controls объясняют причину; отсутствующие функции не выглядят доступными.
Автоматизация различается от редактирования локальных параметров.

### Масштабирование

Проектные размеры для проверки: 1180x760 и 1500x920 logical pixels.
Проверка Windows scaling 100/125/150/200% на доступных дисплеях.
Окончательный minimum size — результат проверки рабочего экрана; без скрытия critical controls и обрезанных значений.
Итоговый visual gate проходит на реальном editor, а не на отдельном showcase.
Существующие UI tokens/components используются после оценки; новый стиль не требует параллельной библиотеки.

## 12. Automation и realtime

Существующие host IDs сохраняются.
Стабильные slot macro endpoints и их назначения восстанавливаются с проектом.
Generate — discrete command; для воспроизведения проекта хранится его результат.
Не обещать корректную запись случайной генерации как обычного continuous automation parameter.

Audio callback:
- без blocking locks, файловых/сетевых операций и unbounded allocation;
- заранее подготовленные event plans, voices и buffers;
- ограниченные event queues и документированный overload policy;
- безопасная передача нового состояния и освобождение старого вне callback;
- ноты и voice ownership привязаны к стабильному SlotId;
- замена инструмента/паттерна и Panic не оставляют висящие ноты;
- latency и tails объявлены корректно.

Нагрузочные бюджеты CPU/RAM/voices фиксируются на согласованном компьютере.
До измерений процент CPU и обещание количества экземпляров не указываются.

## 14. Порядок реализации и критерии перехода

### A. Воспроизведение дефекта и baseline

- Получить точный используемый build и minimal DAW session.
- Отдельно проверить входной MIDI, internal generation, GUI audition, выбранный slot и factory preset.
- Записать короткие dry WAV для одиночной ноты, повторов и generated pattern.
- Проверить прохождение Generate -> context -> provider -> result -> publication -> scheduler -> voice.
- Для «пиип» проверить фактическую высоту, amp sustain/decay, NoteOff, filter mapping и active engine.
- По воспроизведённым дефектам добавить регрессионные проверки.
Выход: известные причины/область дефекта; неизвестное явно отмечено.

### B. Rack contract и одна рабочая Bass-цепочка

- Проверить существующий rack, не переписывать его по факту наличия дефекта в Bass.
- Через тестовый инструмент проверить маршрутизацию, состояние, замену и note ownership.
- Ввести v2 музыкальный контракт/адаптеры с совместимостью до расширения инструментов.
- Довести Bass до слышимого целевого результата.
- Довести Sound/Pattern generation, MIDI export и project restore.
Выход: installable Windows x64 VST3 + Bass + тестовые WAV/MIDI + сценарий проверки в Cubase/Reaper.
Пустой rack не закрывает этот этап.

### C. Drums и kick/bass-контекст

- Kit/pads/choke/pattern lanes.
- Отдельные звуки и MIDI export.
- Согласование с Bass по явному rhythm context.
Выход: устойчивый groove и восстановление kit/resources.

### D. Lead

- Sound generation, мотивы, arp, ручное редактирование.
- Независимость Sound/Pattern, locks, exports и state.
Выход: соответствующий полный пользовательский сценарий.

### E. Keys

- Полифония, аккорды, voice leading, pads/bells/plucks/piano/e-piano.
- Перекрытия нот, sustain и MIDI polyphony.
Выход: корректная harmony phrase и проектное восстановление.

### F. FX

- Семантика событий, длинные переходы, target beat.
- MIDI triggers и точный WAV render с tails.
Выход: корректное размещение перехода в аранжировке.

### G. Пакеты, полный UI и release

- Full-on profiles/presets/scenes для целевой линейки; состав первого коммерческого пакета фиксируется отдельно.
- Pack manifests, compatibility, локальная установка и выбранная политика offline licensing.
- Перекрёстные сцены между пакетами и диагностика отсутствующего контента.
- Полный functional UI, реальные состояния и работающие controls.
- Factory content review, workload/soak, clean install/upgrade/uninstall.
- Матрица DAW/OS и подписанный/версионированный release artifact согласно выбранной политике распространения.
Выход: production acceptance по разделу 15.
Количество пресетов не заменяет качество: контент-план и минимумы утверждаются после приёмки первой Bass-банки.

## 15. Production acceptance

Предлагаемая матрица:
- Windows 10 x64 и Windows 11 x64;
- Cubase 12, 13, 14, 15 x64: scan/open/play/generate/export/state/automation/render;
- REAPER: две зафиксированные стабильные сборки ветки 7.x, включая актуальную на дату заморозки;
- 44.1/48/96 kHz; 64/128/256/512/1024 samples, с фиксацией аппаратных ограничений.

Для каждой поддерживаемой комбинации хоста/ОС указать реально выполненные проверки.
Заявленная совместимость не означает автоматически, что сам производитель DAW поддерживает любую комбинацию Windows/версии хоста.

Обязательные проверки:
1. Clean install, scan, load и повторное открытие editor.
2. Каждая shipped кнопка/ручка меняет реальный state/DSP.
3. Генерация каждого инструмента и ручное редактирование.
4. Sound/Pattern isolation и locks.
5. MIDI drag/import и отсутствие double playback.
6. Exported phrase соответствует captured preview.
7. MIDI channel isolation, layer/splits, note ownership, Panic.
8. Start/stop/seek/loop, смена tempo/block size/sample rate.
9. Automation record/replay и slot mappings.
10. Save/reopen, migration, missing samples, invalid presets.
11. Offline bounce/freeze и воспроизводимость выбранной политики.
12. Multi-instance и dense rack; измерение CPU/RAM, callback allocations.
13. Предлагаемый soak: 8 часов на согласованной машине без crash/hang/stuck notes и необъяснённого роста памяти.
14. Clean-machine offline use без network calls и runtime downloads.
15. Установка/обновление/rollback/uninstall с сохранением user presets.
16. Проверка тембров и generated material прослушиванием владельцем.

Windows host tests и визуально-звуковая приёмка не объявляются выполненными по CTest.
Уровень статуса предложения: требования/дизайн подготовлены; реализация и manual acceptance не выполнены.

## 16. Открытые решения

0. Под отдельными racks владелец подразумевает пакеты внутри общего VST3 или отдельные VST3-продукты?
   Рекомендация: общий host + отдельно поставляемые instrument/style packs; решение не считается согласованным.

1. Есть ли ценные старые проекты/пресеты, которые обязательно открывать?
   До ответа: стабильные идентификаторы и совместимость сохраняются.
2. Какой CPU, RAM, аудиоинтерфейс и обычный ASIO buffer?
   До ответа: измеримые performance promises не заданы.
3. Достаточно ли синтетического piano или требуется реалистическое акустическое?
   До ответа: synth piano, без обещания фотореалистичного рояля.
4. Лицензирование и распространение: personal/open-source/коммерческий продукт.
   До распространения проверить лицензию закреплённой JUCE, SDK и sample content; конкретная платная модель здесь не выбрана.
5. Первый принятый дизайн editor и пределы content bank уточняются по работающей Bass-цепочке.
